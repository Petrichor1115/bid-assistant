> 阅读顺序建议：`prd/README.md`（先理解产品与范围）→ `specs/README.md`（按 01→08 实现）→ `tickets/`（逐条验收）→ `architecture/`（对照整体结构）。

## 5. 维护约定

- PRD 与代码不一致时，**以代码与实际行为为准**，并回写 PRD
- 新增功能先在 `prd/modules` 增补模块文档，再在 `specs` 增加实现步骤，最后在 `tickets` 记录验收
- 文档内不写真实 API Key、真实客户名称与未脱敏的标书数据
