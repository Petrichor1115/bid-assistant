# M2 · 项目管理（子 PRD）

> 模块定位：项目全生命周期的入口与操作中枢。含 4 个页面：项目列表、新建项目、项目详情、已归档列表。

## 模块范围

| 页面 | 路由 | 核心职责 |
|------|------|---------|
| 项目列表 | /workspace/projects | 状态筛选、搜索、分页、入口 |
| 新建项目 | /projects/new | 创建项目 + 上传三件套 |
| 项目详情 | /projects/:id | 信息/文件/版本时间线/操作按钮区 |
| 已归档列表 | /workspace/archived | 只读归档项目 |

**涉及接口**：`GET/POST/PUT/DELETE /api/projects*`、`POST /api/projects/:id/files`、`GET /api/projects/:id/timeline`、`POST /api/projects/:id/agent/run`、`POST /api/projects/:id/submit-approval`、`POST /api/projects/:id/archive`。

## 页面 2.1 项目列表（/workspace/projects）

### 1. 页面核心功能说明
- 展示项目表格；按状态筛选（全部/草稿/进行中/待审批/已归档）；关键字搜索（项目名/招标方）；分页；进入详情入口；[新建项目] 按钮。

### 2. 用户交互流程
```
进入 → 默认全部列表 → 点状态 Tab / 输入关键字 / 翻页 → 刷新列表 → 点行 → /projects/:id
```

### 3. 字段与组件定义

| 字段 | 类型 | 组件 | 说明 |
|------|------|------|------|
| name | string | 文本 | 项目名 |
| bidder | string | 文本 | 招标方 |
| region | string | 文本 | 地区 |
| storage_type | enum | 文本/标签 | 储能场景 |
| status | enum | StatusTag | 状态 |
| deadline | date | 文本 | 截止日期 |
| created_at | datetime | 文本 | 创建时间 |
| 筛选条件 | - | Tabs + Input.Search | 状态/关键字 |
| 分页 | - | Table.pagination | 默认 10/页 |

### 4. 接口请求规范

| 方法 | 路径 | 入参 | 出参 | 时机 |
|------|------|------|------|------|
| GET | /api/projects | `status,keyword,page,pageSize` | `{list,total,page,pageSize}` | 进入/筛选/搜索/翻页 |

### 5. 异常场景处理逻辑

| 场景 | 处理 |
|------|------|
| 列表为空 | 空态"暂无项目" + 引导新建 |
| 接口失败 | message.error，保留筛选条件可重试 |
| 搜索无结果 | 空态"无匹配项目" |

### 6. 权限控制要求
- 用户端 bidder 可见并操作；显示 [新建项目] 按钮。

### 7. UI/UX 设计规范
- 表格列宽：项目名自适应、状态/日期固定宽；状态筛选 Tab 置于表格上方；[新建项目] 主按钮右上。

### 8. 埋点需求

| 事件 | 触发 | 参数 |
|------|------|------|
| project_list_view | 进入页面 | page |
| project_list_filter | 切换状态/搜索 | status, keyword |

### 9. 验收标准
- 筛选/搜索/分页正确；角色按钮可见性正确；空态/错误态正确。

## 页面 2.2 新建项目（/projects/new）

### 1. 页面核心功能说明
- 表单创建项目 + 上传三件套；提交后创建项目并上传文件；对手标书自动归档/缺失自动触发智能匹配。

### 2. 用户交互流程
```
填写项目信息 → 拖拽上传三件套 → 点击 [创建]
 → POST /api/projects 建项目
 → 逐个 POST /api/projects/:id/files 上传
 → 对手标书已传 → 自动归档；未传 → 自动触发 Agent6 匹配
 → 提示成功 → 跳 /projects/:id
```

### 3. 字段与组件定义

| 字段 | 类型 | 组件 | 校验 | 必填 |
|------|------|------|------|:---:|
| name | string | Input | 非空 ≤200 | ✅ |
| bidder | string | Input | ≤200 | - |
| deadline | date | DatePicker | 合法日期 | - |
| region | string | Select/Input | ≤100 | - |
| storage_type | enum | Select | 4 选 1 | - |
| capacity_mwh | number | InputNumber | >0，2 位小数 | - |
| power_mw | number | InputNumber | >0 | - |
| duration_h | number | InputNumber | >0 | - |
| description | text | Input.TextArea | ≤2000 | - |
| 招标公告/我方标书 | file | FileUploader(单文件) | PDF | - |
| 对手标书 | file | FileUploader(多文件) | PDF，≤20 份 | - |

### 4. 接口请求规范

| 方法 | 路径 | 入参 | 出参 | 时机 |
|------|------|------|------|------|
| POST | /api/projects | 项目字段 | `{project}` | 点击创建 |
| POST | /api/projects/:id/files | multipart `file,file_type,version_no` | `{file,archived?}` | 项目创建后逐个上传 |

### 5. 异常场景处理逻辑

| 场景 | 处理 |
|------|------|
| 必填缺失 | 表单红字校验，不提交 |
| 非 PDF / >50MB / 对手>20 份 | 422，message.error |
| 项目创建成功但文件上传失败 | 提示"项目已创建，部分文件上传失败"，跳详情可补传 |
| 智能匹配无结果 | 提示"暂无可匹配对标书"，提供上传入口 |

### 6. 权限控制要求
- 仅 bidder（用户端）可访问。

### 7. UI/UX 设计规范
- 单列表单 + 三个独立上传区（标题区分）；上传区 Dragger；提交按钮底部固定。

### 8. 埋点需求

| 事件 | 触发 | 参数 |
|------|------|------|
| project_create_submit | 点击创建 | storage_type |
| project_create_success | 创建成功 | project_id |
| project_file_upload | 单个文件上传成功 | file_type |

### 9. 验收标准
- 必填校验正确；三件套上传成功；对手标书归档/匹配提示正确。

## 页面 2.3 项目详情（/projects/:id）

### 1. 页面核心功能说明
- 聚合展示：基本信息卡（可编辑）、文件列表（按版本分组）、版本时间线、操作按钮区、Agent 执行状态条、各子页入口。

### 2. 用户交互流程
```
进入 → 加载项目详情+文件+时间线
 → [一键跑 Agent] / [智能匹配] / [上传新版本] / [提交审批] / [项目归档] / [查看报告]
 → 跑 Agent 后轮询状态条直到完成
 → 入口跳转：竞标对比结果 / 对手标书库 / 版本 Diff / 报告
```

### 3. 字段与组件定义

| 区块 | 字段/组件 | 说明 |
|------|----------|------|
| 信息卡 | Descriptions + 编辑 Modal | 项目字段同 2.2 |
| 文件列表 | Table(version_no 分组) | 文件名/类型/大小/时间/下载 |
| 时间线 | VersionTimeline | V1→V2… |
| 按钮区 | Button 组 | 一键跑 Agent(主)、智能匹配、上传新版本、提交审批、归档、查看报告 |
| 状态条 | AgentStatusBar | 主流程 5 Agent + 耗时 |
| 入口 | Link 组 | 竞标对比结果/对手标书库/版本 Diff |

### 4. 接口请求规范

| 方法 | 路径 | 入参 | 出参 | 时机 |
|------|------|------|------|------|
| GET | /api/projects/:id | - | `{project,files,library}` | 进入 |
| PUT | /api/projects/:id | 项目字段 | `{project}` | 编辑保存 |
| GET | /api/projects/:id/timeline | - | `{list}` | 进入 |
| POST | /api/projects/:id/agent/run | `{version_no}` | `{runs}` | 一键跑 |
| POST | /api/projects/:id/agent/:name/run | `{version_no}` | `{run}` | 单跑（调试） |
| GET | /api/projects/:id/agent/runs | `version_no` | `{list}` | 轮询 |
| POST | /api/projects/:id/submit-approval | `{version_no}` | `{approvals,project_status}` | 提交审批 |
| POST | /api/projects/:id/archive | - | `{report}` | 归档 |

### 5. 异常场景处理逻辑

| 场景 | 处理 |
|------|------|
| Agent 运行中 | [一键跑] 禁用；状态条轮询 |
| 部分 Agent failed | 状态条标红，可 [重试]；[提交审批] 禁用 |
| 未 AI 跑通点提交审批 | 按钮禁用 + Tooltip"请先完成 AI 分析" |
| 已归档编辑 | 后端 409，前端隐藏编辑 |
| 无对手标书 | [智能匹配] 可用；对手标书库入口显示空态 |

### 6. 权限控制要求
- bidder（用户端）：全操作；本版无其他登录角色。

### 7. UI/UX 设计规范
- 卡片分区；主操作按钮右侧；状态条实时刷新（1~2s）；危险操作（归档）二次确认。

### 8. 埋点需求

| 事件 | 触发 | 参数 |
|------|------|------|
| project_detail_view | 进入 | project_id |
| agent_run_click | 一键跑 | project_id |
| submit_approval_click | 提交审批 | project_id |
| archive_click | 归档 | project_id |

### 9. 验收标准
- 各区块渲染正确；按钮按状态/权限可用禁用；轮询正常；提交审批门槛生效。

## 页面 2.4 已归档列表（/workspace/archived）

### 1. 页面核心功能说明
- 只读展示 status=archived 的项目，入口查看详情与报告。

### 2. 用户交互流程
```
进入 → 加载 archived 项目列表 → 点行 → /projects/:id（只读）→ 查看报告入口
```

### 3. 字段与组件定义
- 复用项目列表表格（固定 status=archived），增加"查看报告"列。

### 4. 接口请求规范

| 方法 | 路径 | 入参 | 出参 | 时机 |
|------|------|------|------|------|
| GET | /api/projects | `status=archived,page,pageSize` | `{list,total}` | 进入 |

### 5. 异常场景处理逻辑
- 空态"暂无已归档项目"；接口失败 message.error 可重试。

### 6. 权限控制要求
- 用户端 bidder 可见（只读）。

### 7. UI/UX 设计规范
- 同项目列表；行操作仅"查看"。

### 8. 埋点需求
- `archived_list_view`：进入页面。

### 9. 验收标准
- 仅展示已归档；点击可查看详情与报告。
