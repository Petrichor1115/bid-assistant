# M4 · 竞标对比（子 PRD）

> 模块定位：系统核心结果展示域。含 2 个页面：竞标对比结果页（4 Tab）、版本 Diff 页。

## 模块范围

| 页面 | 路由 | 核心职责 |
|------|------|---------|
| 竞标对比结果 | /projects/:id/compare | 自审问题 / 覆盖度 / 竞标差距 / 参数对比 + 推荐卡片 |
| 版本 Diff | /projects/:id/diff | V(N)→V(N+1) 修改点对比 |

**接口**：`GET /api/projects/:id/results`、`GET /api/projects/:id/issues`、`PUT /api/issues/:id`、`GET /api/projects/:id/diff`、`GET /api/projects/:id/competitor-recommendations`、`PUT /api/recommendations/:id/adopt|dismiss`。

---

## 页面 4.1 竞标对比结果页（/projects/:id/compare）

### 1. 页面核心功能说明
- 4 Tab：① 自审问题 ② 招标要求覆盖度 ③ 竞标差距 ④ 参数对比表。
- 顶部展示推荐对标书卡片（可采用/放弃）。
- 差距项按 🔴🟡🟢 分级 + severity 筛选；自审/差距可标记"已解决"。

### 2. 用户交互流程
```
进入 → 加载 results（默认最新已跑通版本）+ 推荐列表
 → Tab 切换 / severity 筛选 / 对手切换下拉
 → 标记已解决 → PUT /api/issues/:id
 → 采用推荐 → PUT adopt → 触发重新对比提示
```

### 3. 字段与组件定义

| Tab | 字段 | 组件 |
|-----|------|------|
| 自审问题 | type/field/current_value/severity/suggestion/is_resolved | Table + SeverityTag + Switch |
| 覆盖度 | req_item/category/our_status/evidence | Table + CoverageTag |
| 竞标差距 | field/our_value/opponent_value/severity/gap_description/suggestion | Table + SeverityTag + 对手切换 Select |
| 参数对比 | fields/our/opponents[] | 二维表（字段×我方/所选对手） |
| 推荐卡片 | company_name/match_score/reason/status | RecommendationCard |

### 4. 接口请求规范

| 方法 | 路径 | 入参 | 出参 | 时机 |
|------|------|------|------|------|
| GET | /api/projects/:id/results | `version_no?,opponent_file_id?` | `{version_no,opponents,self_check,coverage,bid_gaps,param_compare}` | 进入/Tab/切对手 |
| PUT | /api/issues/:id | `{is_resolved}` | `{issue}` | 标记解决 |
| GET | /api/projects/:id/competitor-recommendations | - | `{list}` | 进入 |
| PUT | /api/recommendations/:id/adopt | - | `{recommendation}` | 采用 |

### 5. 异常场景处理逻辑

| 场景 | 处理 |
|------|------|
| 未跑过 Agent | version_no=null，空态"请先运行 Agent" |
| 某 Tab 无数据 | Tab 内空态 |
| 多对手无数据 | 对手下拉仅显示有数据的对手 |
| 采用成功 | message.success + 提示重新跑 Agent 生成对比 |

### 6. 权限控制要求
- bidder（用户端）可标记解决/采用；本版无其他登录角色。

### 7. UI/UX 设计规范
- Tabs 顶部；severity 筛选 Radio；差距表严重度列带色点；参数对比表冻结首列。

### 8. 埋点需求

| 事件 | 触发 | 参数 |
|------|------|------|
| compare_view | 进入 | project_id, version_no |
| compare_tab_switch | 切 Tab | tab |
| compare_severity_filter | 筛选 | severity |
| issue_resolve | 标记解决 | issue_id |

### 9. 验收标准
- 4 Tab 数据正确；分级颜色正确；对手切换生效；标记解决生效；推荐可采用。

## 页面 4.2 版本 Diff（/projects/:id/diff）

### 1. 页面核心功能说明
- 选择 V(N) 与 V(N+1)，对我方标书结构化字段逐项 diff，高亮变更，附修改摘要。

### 2. 用户交互流程
```
进入 → 选择 from/to 版本 → GET diff → 渲染变更列表（新增/删除/变更高亮）→ 查看摘要
```

### 3. 字段与组件定义

| 字段 | 类型 | 组件 | 说明 |
|------|------|------|------|
| from | number | Select | 起始版本 |
| to | number | Select | 目标版本 |
| changes | array | List/Table | field/from_value/to_value/change_type |
| summary | string | 文本 | 修改摘要 |

### 4. 接口请求规范

| 方法 | 路径 | 入参 | 出参 | 时机 |
|------|------|------|------|------|
| GET | /api/projects/:id/diff | `from,to` | `{from,to,changes,summary}` | 选择版本 |

### 5. 异常场景处理逻辑

| 场景 | 处理 |
|------|------|
| 版本不足 2 个 | 空态"暂无可对比版本" |
| from=to | 前端禁用，提示选择不同版本 |

### 6. 权限控制要求
- 全部角色可见（只读）。

### 7. UI/UX 设计规范
- 上下两个 Select；diff 用红/绿/蓝标识 删除/新增/变更。

### 8. 埋点需求
- `diff_view`：进入；`diff_compare`：执行对比（参数 from,to）。

### 9. 验收标准
- 版本选择正确；diff 高亮正确；摘要正确。
