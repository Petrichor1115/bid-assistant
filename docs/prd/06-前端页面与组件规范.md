# 06 · 前端页面与组件规范

> 本章让 AI 开发者直接实现前端。含技术栈、目录、路由、状态、组件与两个前端应用（用户端 web-user / 管理端 web-admin）。

## 1. 技术栈

- Vite 5 + React 18 + TypeScript
- Ant Design 5（组件库）+ @ant-design/icons
- react-router-dom 6（路由）
- axios（HTTP）
- zustand（状态管理）
- dayjs（时间，AntD 依赖）

> 两个应用 `web-user`（用户端）与 `web-admin`（管理端）为两个独立 Vite 项目，共享同一后端 `server`（`/api` 代理）与 MySQL。types/api 允许各自独立实现（MVP 不强制抽公共包）。

## 3. 路由表

### 3.1 用户端 web-user

| 路径 | 页面 | 鉴权 | 说明 |
|------|------|------|------|
| `/login` | Login | 否 | 固定投标专员，无角色下拉 |
| `/` | ChatHome | 是 | 对话式主页 |
| `/workspace` | WorkspaceLayout | 是 | 项目工作台容器，默认重定向 `/workspace/projects` |
| `/workspace/projects` | ProjectList | 是 | 项目列表 |
| `/workspace/dashboard` | WorkspaceDashboard | 是 | 个人仪表盘（并入工作台） |
| `/workspace/archived` | ArchivedList | 是 | 已归档列表 |
| `/projects/new` | ProjectNew | 是 | 新建项目 |
| `/projects/:id` | ProjectDetail | 是 | 项目详情 |
| `/projects/:id/compare` | BidCompareResult | 是 | 竞标对比结果 |
| `/projects/:id/library` | CompetitorLibrary | 是 | 对手标书库 |
| `/projects/:id/diff` | VersionDiff | 是 | 版本 Diff |
| `/projects/:id/report` | ProjectReport | 是 | 项目总报告 |

**鉴权守卫**：无 token → 跳 `/login`；用户端仅 `bidder` 可访问，否则登出回登录页。

### 3.2 管理端 web-admin

| 路径 | 页面 | 鉴权 | 说明 |
|------|------|------|------|
| `/login` | Login | 否 | 仅 admin |
| `/admin` | AdminDashboard | admin | 系统仪表盘 |
| `/admin/users` | UserManagement | admin | 用户管理 |
| `/admin/conversations` | ConversationManagement | admin | 对话管理（置灰） |
| `/admin/knowledge` | KnowledgeManagement | admin | 知识库管理（置灰） |

## 4. 状态管理

### authStore（两个应用各自持有）

```ts
{ token: string | null, user: User | null,
  login(username,password): Promise<void>,
  logout(): void,
  fetchMe(): Promise<void> }
```

### projectStore（仅用户端，用于结果缓存）

```ts
{ currentProject: Project | null, results: Results | null,
  setProject(p), setResults(r) }
```

## 5. HTTP 封装（api/http.ts）

- baseURL：`/api`（Vite 代理到 `http://localhost:3001`）。
- 请求拦截器：附加 `Authorization: Bearer ${token}`。
- 响应拦截器：`code !== 0` 时 `message.error(message)` 并 reject。
- 统一导出 `get/post/put/del`。

**Vite 代理配置（两个应用一致）**：

```ts
server: { proxy: { '/api': 'http://localhost:3001', '/uploads': 'http://localhost:3001' } }
```

## 6. 布局

### 6.1 ChatLayout（对话式主页 `/`）

- **左侧导航**（约 240px）：
  - 用户信息：`[头像] [姓名] [退出按钮]`（退出在名字右侧）。
  - 功能模块（分组标题）：
    - 标讯追踪 / 招标解读 / 标书生成 / 标书审查 → `GreyedItem`（点击弹「敬请期待」）。
    - 竞标对比 → 可点，跳 `/workspace/projects`。
  - 对话模块（分组标题）：
    - 新建对话 / 对话记录 → `GreyedItem`。
  - 项目模块（分组标题）：
    - 新建项目 → `/projects/new`。
    - 项目列表（最近 3 个，按 `updated_at` 倒序）：单条 → `/projects/:id`；「查看全部」→ `/workspace/projects`。
    - 我的项目 → `/workspace/projects`。
- **右侧对话框**（主内容区）：
  - 对话主框：文字输入框（`GreyedItem`）+ 上传文件按钮（`GreyedItem`）。
  - 快捷按钮：我的项目（首、尾各一，行为一致）→ `/workspace/projects`；标讯追踪 / 招标解读 / 标书生成 / 标书审查 / 竞标对比 → `GreyedItem`。
  - 标讯推荐：5 张 `TenderCard`（矢量 SVG 图 + 名称），**写死**静态不可点，位于输入框下方、靠近页面底部。
- **数据**：项目列表最近 3 调 `GET /api/projects?page=1&pageSize=3&sort=updated_at`（后端若未实现 sort，则前端取列表后按 `updated_at` 倒序取 3）。

### 6.2 WorkspaceLayout（项目工作台）

- 二级侧边栏：仪表盘 / 项目列表 / 已归档。
- 进入项目后按项目内导航：项目详情 / 竞标对比结果 / 对手标书库 / 版本 Diff / 项目报告。
- 内容区：`<Outlet />`。

### 6.3 AdminLayout（管理端）

- 左侧菜单：系统仪表盘 / 用户管理 / 对话管理（`GreyedItem`）/ 知识库管理（`GreyedItem`）。
- 顶栏：系统名 + 当前用户 + 退出。
- 内容区：`<Outlet />`。

## 7. 页面规格

### 7.1 Login（用户端）
- 表单：用户名、密码（**无角色下拉**，固定投标专员）。
- 提交 → `authStore.login` → 跳 `/`（对话式主页）。

### 7.2 ChatHome（对话式主页）
- 见 6.1 ChatLayout 布局与交互规格。

### 7.3 WorkspaceDashboard（个人仪表盘，并入工作台）
- 状态卡片 4 个（draft/in_progress/awaiting_approval/archived 计数）。
- 最近活动时间线（`GET /api/dashboard`）。

### 7.4 ProjectList
- 状态筛选 Tab + 搜索框 + AntD Table（分页）。
- 行点击 → `/projects/:id`。
- [新建项目] 按钮。

### 7.5 ProjectNew
- AntD Form + DatePicker + Select（储能场景）。
- 3 个 FileUploader（招标公告单文件 / 我方标书单文件 / 对手标书多文件）。
- 提交：先 `POST /api/projects`，再逐个 `POST /api/projects/:id/files`。
- 提交成功 → 若对手标书为空，展示「已触发智能匹配」提示 → 跳项目详情。

### 7.6 ProjectDetail
- 基本信息卡（Descriptions）+ 编辑（Modal）。
- 文件列表（Table，按版本分组）。
- 版本时间线（VersionTimeline）。
- 按钮区：[一键跑 Agent]（主）、[智能匹配对手标书]（无对手标书时显示）、[上传新版本]、[提交审批]、[项目归档]、[查看报告]。
- AgentStatusBar（轮询）。
- 入口：竞标对比结果、对手标书库、版本 Diff、项目报告。
- [提交审批] 禁用逻辑：最新版本 5 个主流程 Agent（Agent6 除外）未全部 success。

### 7.7 BidCompareResult（核心，原 CompareResult）
- Tabs：自审问题 / 招标要求覆盖度 / 竞标差距 / 参数对比表。
- 每 Tab 内支持 severity 筛选。
- 自审问题/竞标差距：Table（SeverityTag + 建议）+ 行内「标记已解决」。
- 覆盖度：Table（CoverageTag + 证据）。
- 竞标差距/参数对比表：顶部**对手切换下拉**（默认最新归档一份，多对手逐份切换）。
- 参数对比表：二维表（字段 × 我方/所选对手）。
- 顶部 RecommendationCard 列表（采用/放弃按钮）。

### 7.8 CompetitorLibrary
- 本库条目 Table（公司名/行业/规模/类型/索引状态）。
- 推荐列表 Table（公司名/得分/理由/状态/采用按钮）。
- [智能匹配] 按钮。

### 7.9 VersionDiff
- 两个 Select 选择 from/to 版本。
- diff 结果高亮（AntD Descriptions 或自定义 diff 渲染）。

### 7.10 ProjectReport
- 版本时间线 + 问题分类饼图 + 耗时统计。
- [导出 PDF] → 打开 `/api/projects/:id/report/pdf`。

### 7.11 ArchivedList
- 复用 ProjectList（固定 status=archived 只读），点击查看详情/报告。

### 7.12 管理端页面
- **Login**：用户名、密码（无角色下拉，固定 admin）→ `/admin`。
- **AdminDashboard**：系统统计卡片（`GET /api/admin/dashboard`）。
- **UserManagement**：用户列表 Table（`GET /api/users`）。
- **ConversationManagement / KnowledgeManagement**：置灰占位页（导航项用 `GreyedItem`，点击弹「敬请期待」，本版不进入页面亦可）。

## 8. 通用组件规格

### StatusTag
- props: `status`；映射颜色（见 02 第 8 节）。

### SeverityTag
- props: `severity`；red=🔴红 / yellow=🟡黄 / green=🟢绿。

### CoverageTag
- props: `status`；covered=✅绿 / missing=❌红 / not_met=⚠️橙。

### AgentStatusBar
- props: `runs`；展示主流程 5 个 Agent 的步骤条（Steps）+ 各自耗时；轮询刷新。

### FileUploader
- props: `accept`, `multiple`, `onChange`；用 AntD Upload.Dragger。

### GreyedItem（置灰项）
- props: `label`, `icon?`。
- 视觉置灰、可点击；点击 `message.info('敬请期待')`（**非 disabled**）。

### TenderCard（标讯推荐静态卡片）
- props: `icon`（SVG 矢量图）, `name`。
- 写死静态渲染，不可点击。

## 9. 类型定义（types/index.ts，与 API 对齐）

```ts
type Role = 'bidder'|'tech_lead'|'legal'|'bid_director'|'admin';
type ProjectStatus = 'draft'|'in_progress'|'awaiting_approval'|'approved'|'archived'|'rejected';
type StorageType = 'residential'|'commercial'|'utility'|'ems_battery';
type FileType = 'announcement'|'our_bid'|'competitor_bid';
type AgentName = 'parse_announcement'|'parse_document'|'quality_check'|'requirement_coverage'|'bid_compare'|'competitor_match';
type AgentStatus = 'pending'|'running'|'success'|'failed';
type IssueCategory = 'self_check'|'requirement_gap'|'bid_gap';
type Severity = 'red'|'yellow'|'green';

interface User { id: string; name: string; role: Role; department?: string; }
interface Project { id: string; name: string; bidder?: string; deadline?: string;
  region?: string; storage_type?: StorageType;
  capacity_mwh?: number; power_mw?: number; duration_h?: number; description?: string;
  status: ProjectStatus; creator_id: string; created_at: string; updated_at?: string; }
interface FileRecord { id: string; project_id: string; version_no: number;
  file_type: FileType; original_name: string; storage_url: string;
  file_size: number; created_at: string; }
interface AgentRun { id: string; project_id: string; version_no: number;
  agent_name: AgentName; status: AgentStatus; error_message?: string;
  started_at?: string; finished_at?: string; duration_ms?: number; }
interface Issue { id: string; project_id: string; version_no: number;
  category: IssueCategory; severity: Severity; field_key?: string;
  field_label?: string; our_value?: string; opponent_value?: string;
  gap_description?: string; suggestion?: string; source_agent?: string;
  is_resolved: number; created_at: string; }
interface Recommendation { id: string; source_entry_id: string; source_file_id?: string;
  company_name: string; match_score: number; match_features_json?: string;
  recommendation_reason?: string; status: 'recommended'|'adopted'|'dismissed'; }

interface CoverageItem { req_item: string; category: string;
  our_status: 'covered'|'missing'|'not_met'; evidence?: string; }

interface OpponentParam { file_id: string; company_name: string; params: Record<string, unknown>; }

interface Results { version_no: number | null;
  opponents: { file_id: string; company_name: string }[];
  self_check: Issue[]; coverage: CoverageItem[]; bid_gaps: Issue[];
  param_compare: { fields: string[]; our: Record<string, unknown>; opponents: OpponentParam[] }; }
```
