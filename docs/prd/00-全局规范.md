## 4. 全局错误码

| HTTP | 含义 |
|:---:|------|
| 400 | 参数错误 |
| 401 | 未登录/token 无效 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 409 | 状态冲突（已归档不可改、非 approved 不可归档、重复提交审批） |
| 422 | 业务校验失败（未 AI 跑通不可提交审批、文件非法） |
| 500 | 服务器错误 |

响应信封：成功 `{code:0, message:"ok", data}`；失败 `{code, message, data:null}`。

## 5. 权限模型

### 5.1 页面可见性矩阵（两个应用）

| 应用 | 登录角色 | 页面 |
|------|---------|------|
| web-user（用户端） | bidder（固定，无角色下拉） | 对话式主页、项目工作台（仪表盘 / 项目列表 / 已归档）、新建项目、项目详情、竞标对比结果、对手标书库、版本 Diff、项目报告 |
| web-admin（管理端） | admin | 系统仪表盘、用户管理、对话管理（置灰）、知识库管理（置灰） |

> `tech_lead` / `legal` / `bid_director` 仅作为审批流角色保留于数据模型（MVP 自动审批通过），本版不提供登录页与页面。

### 5.2 按钮级权限

| 操作 | 允许角色 |
|------|---------|
| 新建/编辑/删除项目、上传文件、跑 Agent、提交审批、归档、采用对标书 | bidder（用户端） |
| 用户 CRUD | 仅 admin（管理端） |
| 只读浏览 | 全部角色（仅读，无操作按钮） |

## 6. 全局 UI/UX 规范

- 组件库 Ant Design 5，中文文案，主色 `#1677ff`。
- 状态标签色：draft=default(灰)、in_progress=blue、awaiting_approval=orange、approved=green、archived=default、rejected=red。
- 严重度色：red=红、yellow=黄、green=绿（配合 emoji 🔴🟡🟢）。
- 覆盖状态色：covered=绿、missing=红、not_met=橙。
- 表格：分页默认 10 条/页；空态展示"暂无数据"；加载中 Spin；错误统一 `message.error`。
- 表单：必填项红星；日期 DatePicker（YYYY-MM-DD）；数值 InputNumber；提交按钮 loading。
- 布局：用户端为左侧导航（用户信息/功能模块/对话模块/项目模块）+ 右侧对话主框；项目工作台为二级侧边栏 + 内容区；管理端为左侧菜单 + 顶栏。桌面优先，≥1280 三栏、768~1280 两栏、<768 抽屉式菜单。
- **置灰**：视觉置灰、可点击，点击弹 Toast「敬请期待」（非 disabled）。
- **写死**：前端硬编码静态渲染，不可交互（如首页标讯推荐 5 张卡片）。
- 危险操作（删除/归档）二次确认 Modal。

## 7. 全局埋点规范

- 事件命名：`{模块}_{动作}`，如 `login_submit`、`project_create_submit`、`agent_run_click`、`compare_tab_switch`、`recommend_adopt_click`。
- 公共参数：`user_id`、`role`、`project_id`（如适用）、`page`、`ts`。
- 上报方式：前端统一埋点函数 `track(event, params)`；MVP 可 console/本地存储，预留后端 `POST /api/track` 扩展。
