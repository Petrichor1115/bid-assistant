## T01 · 存储适配器 storageAdapter.js（local）

- **描述**：实现本地文件存储统一接口，并在 app 挂载静态 `/uploads`。
- **交付物**：`server/src/services/storage/storageAdapter.js`
- **要点**：`save(fileBuffer, destName)` 写 `STORAGE_DIR`，返回 `{path: destName, url:'/uploads/'+destName}`；`remove(path)`；`app.use('/uploads', express.static(STORAGE_DIR))`。
- **验收**：上传文件后 `GET /uploads/{uuid}` 可访问；remove 可删除。
- **依赖**：Spec 01（app.js）

## T02 · projectController：项目 CRUD

- **描述**：实现项目列表/创建/查询/更新/删除。
- **交付物**：`server/src/controllers/projectController.js`
- **要点**：
  - list：`status` 等值、`keyword LIKE name|bidder`、`page/pageSize`、`sort=updated_at` 时按 updated_at DESC，否则 `created_at DESC`
  - create：`name` 必填（422），status=draft，含 `capacity_mwh/power_mw/duration_h`
  - get：返回 `{project, files, library}`（library 可为 null）
  - update：`status=archived` → 409；部分字段更新
  - delete：级联删除子表记录
- **验收**：CRUD + 筛选/搜索/分页正确；archived 编辑 → 409。
- **依赖**：Spec 02（表）、Spec 03（auth）

## T03 · projectController：版本时间线 timeline

- **描述**：按 `version_no` 聚合返回版本时间线。
- **交付物**：`server/src/controllers/projectController.js`（追加）
- **要点**：返回 `[{version_no, file_count, agent_status, created_at}]`，版本倒序。
- **验收**：V1→V2 时间线正确。
- **依赖**：T02

## T04 · routes/projects.js 挂载 + 权限

- **描述**：挂载项目 7 端点，写操作限 bidder。
- **交付物**：`server/src/routes/projects.js`；`app.js` 注册。
- **要点**：GET `/projects`、`/projects/:id`、`/projects/:id/timeline` 走 `auth`；POST/PUT/DELETE 走 `requireRole('bidder')`。
- **验收**：非 bidder 写操作 → 403。
- **依赖**：T02、T03、Spec 01 T05

## T05 · fileController：文件上传（multer + 版本语义 + 入库钩子）

- **描述**：接收 multipart 上传，校验后写 files，对手标书触发入库钩子。
- **交付物**：`server/src/controllers/fileController.js`（上传部分）
- **要点**：
  - `multer` 内存/磁盘存储；校验 PDF、单文件 ≤50MB、对手标书 ≤20 份，否则 422
  - `version_no`：our_bid/announcement 跟随项目版本；competitor_bid 仅作归档时点标记
  - 写 files（storage_path/storage_url 来自 T01）
  - `file_type==='competitor_bid'` → 调用 `archiveService.archiveCompetitorBid(projectId,file)`（Spec 05，先留桩）
- **验收**：三件套上传成功；非 PDF/超限 → 422；对手标书触发入库钩子。
- **依赖**：T01

## T06 · fileController：列表/下载/删除

- **描述**：实现文件列表、下载、删除（含对手标书级联与计数）。
- **交付物**：`server/src/controllers/fileController.js`（追加）、`server/src/routes/files.js`
- **要点**：
  - list：`version_no/file_type` 筛选
  - download：读文件流，`Content-Disposition` 附件
  - delete：对手标书 → 级联删 entry + 推荐（DB 外键），并手动 `entry_count - 1`
- **验收**：列表/下载正确；删除对手标书后 entry_count 递减、推荐级联删除。
- **依赖**：T05

## T07 · 版本 Diff 接口

- **描述**：实现 V1/V2 我方标书结构化字段逐项 diff。
- **交付物**：`server/src/controllers/fileController.js`（追加）或 `diffController.js`
- **要点**：读取两版本 `agent_runs.output_json` 的我方字段，输出 `{from,to,changes:[{field,from_value,to_value,change_type}],summary}`。
- **验收**：V1/V2 diff 高亮正确。
- **依赖**：T06

## T08 · 项目与文件模块联调验证

- **描述**：端到端验证项目与文件全流程。
- **交付物**：验证记录（`docs/tickets/verify-04.md`）
- **验收**（对应 Spec 04 §6）：
  1. 项目 CRUD + 筛选/搜索/分页正确；archived 编辑 → 409
  2. 三件套上传成功、可下载；非 PDF/超限 → 422
  3. 上传对手标书触发入库钩子
  4. 删除项目级联正确；diff 逐项高亮
- **依赖**：T04、T06、T07
