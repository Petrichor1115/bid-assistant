# Spec 02 · 数据模型与数据库

> 依赖：Spec 01　|　对应里程碑：M1　|　参考：[03-数据模型与MySQL设计.md](../prd/03-数据模型与MySQL设计.md)

## 1. 目标
在 MySQL 8.0（≥8.0.16）建库 `bid_demo`、建 10 张表 + 索引 + 种子数据，提供 mysql2 连接池与迁移/种子脚本。

## 2. 范围
- **含**：完整 DDL、索引、`scripts/migrate.js`、`seed.js`、`src/db/index.js` 连接池。
- **不含**：业务逻辑（后续 Spec）。

## 3. 交付物
```
server/schema.sql
server/scripts/migrate.js
server/seed.js
server/src/db/index.js     # mysql2/promise 连接池单例
```

## 4. 完整 DDL（schema.sql 要点，全文见 PRD 03）

```sql
CREATE DATABASE IF NOT EXISTS bid_demo DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE bid_demo;

CREATE TABLE IF NOT EXISTS users (
  id VARCHAR(36) PRIMARY KEY, name VARCHAR(100) NOT NULL, password_hash VARCHAR(255) NOT NULL,
  role VARCHAR(50) NOT NULL, department VARCHAR(100) NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP, updated_at DATETIME NULL,
  CONSTRAINT chk_users_role CHECK (role IN ('bidder','tech_lead','legal','bid_director','admin'))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS projects (
  id VARCHAR(36) PRIMARY KEY, name VARCHAR(200) NOT NULL, bidder VARCHAR(200) NULL,
  deadline DATE NULL, region VARCHAR(100) NULL, storage_type VARCHAR(50) NULL,
  capacity_mwh DECIMAL(12,2) NULL, power_mw DECIMAL(12,2) NULL, duration_h DECIMAL(10,2) NULL,
  description TEXT NULL, status VARCHAR(30) NOT NULL DEFAULT 'draft',
  creator_id VARCHAR(36) NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP, updated_at DATETIME NULL,
  CONSTRAINT chk_projects_storage_type CHECK (storage_type IN ('residential','commercial','utility','ems_battery')),
  CONSTRAINT chk_projects_status CHECK (status IN ('draft','in_progress','awaiting_approval','approved','archived','rejected')),
  CONSTRAINT fk_projects_creator FOREIGN KEY (creator_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- files / agent_runs / issues / approvals / project_reports /
-- competitor_bid_libraries / competitor_bid_entries / bid_recommendations
-- 字段与 CHECK/外键/索引详见 PRD 03，全部 InnoDB + utf8mb4
```

> 关键点：`files.version_no`（announcement/our_bid 跟随项目版本；competitor_bid 仅归档时点标记）；`issues` 幂等；`bid_recommendations.source_file_id` 用 `ON DELETE SET NULL`；`agent_runs.agent_name` 含 6 个枚举（含 competitor_match）。
> 命名统一（v3.0）：`agent_runs.agent_name` 的 `competitor_compare→bid_compare`、`issues.category` 的 `competitor_gap→bid_gap`、`project_reports.competitor_gap_count→bid_gap_count`。本版**不新增** conversation/message 表。

## 5. 连接池与迁移

```js
// src/db/index.js
const mysql = require('mysql2/promise');
module.exports = mysql.createPool({
  host: process.env.DB_HOST, port:+process.env.DB_PORT||3306,
  user: process.env.DB_USER, password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME, waitForConnections:true, connectionLimit:10,
  timezone:'Z'
});

// scripts/migrate.js —— 用 multipleStatements:true 执行 schema.sql 全文
```

## 6. 种子（seed.js）
- 若 `users` 为空，插入 5 用户（bidder/tech_lead/legal/bid_director/admin，密码 `123456` bcrypt hashSync 运行时生成）。
- 可选：插入 1 示例项目 + 1 库 + 1 条目 + 1 对手文件（见 PRD 09 3.9）。

## 7. 验收标准
- `npm run db:migrate` 无报错，10 表 + 索引建立。
- `npm run seed` 后 5 用户可查询、密码哈希正确。
- 枚举 CHECK 生效（插入非法 role 被拒绝）。
