# Spec 06 · 结果、审批、归档与报告

> 依赖：Spec 05　|　对应里程碑：M5　|　参考：[04-API接口规范.md](../prd/04-API接口规范.md)、[modules/04](../prd/modules/04-竞标对比.md)、[modules/06](../prd/modules/06-报告与统计.md)

## 1. 目标
实现分析结果聚合、issues 维护、三级自动审批、项目归档、报告生成与 PDF 导出。

## 2. 范围
- **含**：results/issues（4 端点）、approvals（2 端点）、archive/report/pdf（3 端点）。
- **不含**：Agent 执行（Spec 05）、前端。

## 3. 交付物
```
server/src/routes/results.js
server/src/routes/approvals.js
server/src/routes/reports.js
server/src/controllers/{result,approval,report}Controller.js
server/src/services/report/reportGenerator.js   # 统计 + pdfkit
```

## 4. 接口规范

| 方法 | 路径 | 鉴权 | 入参 | 出参 |
|------|------|------|------|------|
| GET | /api/projects/:id/results | 是 | `version_no?,opponent_file_id?` | `{version_no,opponents,self_check,coverage,bid_gaps,param_compare}` |
| GET | /api/projects/:id/issues | 是 | `category,severity,version_no,page,pageSize` | `{list,total}` |
| PUT | /api/issues/:id | bidder | `{is_resolved}` | `{issue}` |
| POST | /api/projects/:id/submit-approval | bidder | `{version_no}` | `{approvals,project_status:"approved"}` |
| GET | /api/projects/:id/approvals | 是 | - | `{list}` |
| POST | /api/projects/:id/archive | bidder | - | `{report}` |
| GET | /api/projects/:id/report | 是 | - | `{report}` |
| GET | /api/projects/:id/report/pdf | 是 | - | PDF 文件流 |

## 5. 核心逻辑

```js
// results：默认 version_no = 有 success 运行记录的最大版本（无则 version_no=null 空结果）
// param_compare = { fields, our, opponents:[{file_id,company_name,params}] }，按 opponent_file_id 过滤
// coverage 从 Agent4 output_json 解析；self_check/bid_gaps 读 issues 表

// submit-approval：
//   校验 status∈{draft,in_progress} 否则 409；
//   校验 5 主流程 Agent 全 success（Agent6 不纳入）否则 422；
//   生成 3 条 approvals（tech_lead→legal→bid_director，decision=approved,auto_approved=1）
//   项目 status → awaiting_approval → approved

// archive：status 必须 approved 否则 409；汇总版本/问题/耗时 → project_reports
//   final_summary 无 LLM 用模板："项目共迭代 N 版，累计耗时 X 小时；自审 a 项、招标差距 b 项、竞标差距 c 项，其中致命 d 项。"
//   status → archived

// report/pdf：pdfkit 生成（统计卡片 + 表格 + 摘要）
```

## 6. 验收标准
- results 4 类数据正确、多对手按 opponent_file_id 过滤、未跑过返回 version_no=null。
- 未 AI 跑通提交审批 → 422；跑通后三级自动通过、status=approved。
- 非 approved 归档 → 409；归档生成报告、PDF 可下载、status=archived。
