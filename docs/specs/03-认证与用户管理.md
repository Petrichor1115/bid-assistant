# Spec 03 · 认证与用户管理

> 依赖：Spec 02　|　对应里程碑：M2　|　参考：[04-API接口规范.md](../prd/04-API接口规范.md)、[modules/01](../prd/modules/01-认证与权限.md)

## 1. 目标
实现 JWT 登录与用户 CRUD（admin），含鉴权中间件与路由守卫所需接口。

## 2. 范围
- **含**：`POST /api/auth/login`、`GET /api/auth/me`、`POST /api/auth/logout`、用户 CRUD（5 个端点）。
- **不含**：页面（Spec 07）。

## 3. 交付物
```
server/src/routes/auth.js
server/src/routes/users.js
server/src/controllers/authController.js
server/src/controllers/userController.js
server/src/middleware/auth.js
```

## 4. 接口规范

| 方法 | 路径 | 鉴权 | 入参 | 出参 | 错误 |
|------|------|------|------|------|------|
| POST | /api/auth/login | 无 | `{username,password,app(user|admin)}` | `{token,user}` | 401 用户名/密码错、app 与角色不符 |
| GET | /api/auth/me | 是 | - | `{user}` | 401 |
| POST | /api/auth/logout | 是 | - | `{message:"ok"}` | - |
| GET | /api/users | admin | `page,pageSize,keyword,role` | `{list,total,page,pageSize}` | 403 |
| POST | /api/users | admin | `{name,password,role,department}` | `{user}` | 422 重名/密码空 |
| GET | /api/users/:id | admin | - | `{user}` | 404 |
| PUT | /api/users/:id | admin | `{name?,password?,role?,department?}` | `{user}` | 404 |
| DELETE | /api/users/:id | admin | - | `{message:"ok"}` | 422 删自己/最后 admin |

## 5. 核心逻辑
```js
// login
const u = await db.query('SELECT * FROM users WHERE name=?',[username]);
if(!u || !bcrypt.compareSync(password, u.password_hash)) return 401;
const need = app==='admin' ? 'admin' : 'bidder';
if(u.role !== need) return 401 '账号与当前应用角色不匹配';
const token = jwt.sign({id:u.id, name:u.name, role:u.role}, JWT_SECRET, {expiresIn:'7d'});
return {token, user:{id,name,role,department}};
// user 返回一律剔除 password_hash
```

## 6. 验收标准
- 正确账号+app → 返回 token；app 与角色不符（如用户端用 admin 账号）→ 401。
- 无 token 调 `/api/auth/me` → 401；管理端 admin 可 CRUD；用户端 bidder 调 users → 403。
- 删除自己或最后一个 admin → 422。
